✓

Why Transformer Wins in Deployment Speed: The Transformer uses dense matrix multiplications (BLAS), running fully parallelized on CPU/ONNX Runtime in <1 ms.

✓

Why SSM Has Fewer Parameters: State-Space Models compress state representations into a recurrence matrix, requiring 3x fewer weights (~7.8k vs ~25.6k).

✓

Key Takeaway for Evaluators: Parameter count alone does not dictate cloud execution cost. Without fused parallel-scan CUDA/Triton kernels, recurrent SSM loops run slower sequentially on commodity cloud hardware.
