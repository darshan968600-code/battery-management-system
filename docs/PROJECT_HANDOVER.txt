2. ARTIFICIAL INTELLIGENCE MODEL SPECIFICATIONS
--------------------------------------------------------------------------------
Model Artifact File   : transformer(1).onnx
Integrity Hash (SHA256): 00c1c87675150f615d0ab5fbfa30577dd5099133ad422778c4a30aeb01c6a519
Binary Size           : 221,528 bytes (~216 KB)
Model Architecture    : 2-Layer Transformer Encoder with Self-Attention
Positional Encoding   : Fixed Learned Positional Embedding [1, 512, 32]
Parameter Count       : ~25,600 trainable parameters
Inference Runtime     : Microsoft ONNX Runtime (CPU execution provider)
CPU Latency           : 0.62 ms - 0.68 ms per inference window

Input Specification:
  - Input Tensor Name : "input"
  - Input Dimensions  : [batch_size, 32, 3] (Float32)
  - Timestep Window   : 32 sequential readings
  - Feature Channels  : 3 channels per timestep:
      1. Voltage (V)
      2. Current (A)
      3. Temperature (C)

Output Specifications (Dual Prediction Heads):
  - Head 1 ("soc_output"):
      Shape: [batch_size, 1]
      Activation: Sigmoid (bounded [0.0, 1.0])
      Represents: State of Charge (SOC %) = soc_raw * 100
  - Head 2 ("soh_output"):
      Shape: [batch_size, 1]
      Activation: Linear regression
      Represents: State of Health (SOH) capacity retention metric (1.0 = 100% nominal)

Guardrails & Safety Clamping:
  - Linear SOH outputs are automatically clamped to [0.0, 1.5] by the backend
    guardrail layer to eliminate floating-point drift anomalies.
  - Automatic status classification:
      * SOH >= 0.85                  -> "NORMAL"
      * 0.70 <= SOH < 0.85           -> "DEGRADED_BATTERY"
      * SOH < 0.70 or Abnormal Temp  -> "CRITICAL_ACTION_REQUIRED"

7. REST API ENDPOINT REFERENCE
--------------------------------------------------------------------------------
Base URL: https://battery-bms.duckdns.org

1. GET /
   Returns: Interactive HTML Single-Page Dashboard.

2. GET /docs
   Returns: Interactive OpenAPI / Swagger documentation for developers.

3. GET /health
   Returns: JSON server health, model loaded state, active filename, and window size.
   Example Response:
   {
     "status": "healthy",
     "model_loaded": true,
     "model_file": "transformer(1).onnx",
     "window_size": 32
   }

4. GET /model/info
   Returns: Active configuration, normalization factors, and guardrail limits.

5. POST /predict
   Accepts: 32 timesteps of [Voltage, Current, Temperature].
   Payload:
   {
     "window": [
       [3.82, -1.25, 25.4],
       ... (32 items)
     ]
   }
   Response:
   {
     "soc_percentage": 26.92,
     "soc_raw": 0.2692,
     "soh_metric": 0.6931,
     "battery_status": "DEGRADED_BATTERY",
     "inference_time_ms": 0.62
   }

6. POST /predict/channels
   Accepts: 3 separate lists of 32 readings: "voltage", "current", "temperature".

7. POST /model/reload
   Hot-reloads model weights and configuration dynamically with zero server downtime.

8. GET /fleet/list
   Returns: High-level summary of all 5 operational fleets.

9. GET /fleet/{fleet_id}
   Returns: Detailed telemetry and status for all packs in the chosen fleet.

10. GET /fleet/{fleet_id}/{pack_id}
    Returns: Detailed 32-step sensor arrays for an individual battery pack.

11. GET /dataset/benchmarks?cell={B0005|B0006|B0007|B0018}
    Returns: Raw NASA cycle degradation data points for graphing.

12. GET /benchmark/comparison
    Returns: Empirical comparison metrics between Transformer and SSM architectures.

9. PROCEDURE TO HOT-SWAP A FUTURE MODEL (ZERO-DOWNTIME)
--------------------------------------------------------------------------------
When a newly trained model is ready (e.g., "transformer_v2.onnx"):

Step 1: Upload the new model to the EC2 server:
  scp -i "bms-key.pem" transformer_v2.onnx ubuntu@13.203.220.49:/home/ubuntu/bms_api/

Step 2: Update "model_file" inside config.json:
  {
    "model_file": "transformer_v2.onnx",
    "version": "2.0.0",
    ...
  }
  Upload updated config.json:
  scp -i "bms-key.pem" config.json ubuntu@13.203.220.49:/home/ubuntu/bms_api/

Step 3: Trigger the hot-reload endpoint:
  curl.exe -X POST https://battery-bms.duckdns.org/model/reload

Result: The server instantly swaps the active model in memory with ZERO downtime
and without stopping the background systemd service.
